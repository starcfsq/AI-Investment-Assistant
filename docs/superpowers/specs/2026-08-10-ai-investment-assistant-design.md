# AI 智能投资助手（A股 · 长期投资规划）设计文档

- 日期：2026-08-10
- 仓库：`git@github.com:starcfsq/AI-Investment-Assistant.git`
- 定位：用于 LLM/大模型应用开发岗位面试的完整项目

## 1. 产品概述

一个面向 A 股长期投资者的智能投资助手。核心链路：

```
大盘长期趋势分析 → 板块机会识别 → 股票/基金筛选 → 长期配置建议
```

交互形态为**可视化看板 + 对话问答**：看板展示市场趋势指标、板块热度、推荐标的；对话支持对看板数据的深度问答、以及基于新闻/公告的知识检索问答。

## 2. 目标与面试亮点

1. **工程化深度**：分层架构、单元测试、mock 数据层、结构化日志、错误降级。
2. **RAG 能力**：新闻/公告检索问答，回答带来源引用。
3. **Agent/工具调用**：分析引擎作为确定性"工具"，LLM 调用其输出做解读。
4. **评估体系**：黄金场景集 + 一致性校验 + 检索质量评估，证明"系统有效"。
5. **数据溯源**：每个数字有来源、时点、计算记录；AI 论点可回溯。
6. **诚实设计**：置信度、不确定性说明、投资免责声明。

## 3. 核心设计原则

> **数据永不来自 LLM。**

- 所有数字（指数、估值、板块涨幅、财务指标）由确定性分析引擎从 akshare 真实数据计算。
- DeepSeek 只负责把分析结果翻译为自然语言解读、推荐理由、规划建议。
- LLM 不接触原始行情，不生成任何数字，不引入编造信息。
- 分析结果同时供给前端（渲染看板）与 LLM（生成解读），保证二者一致。

## 4. 技术栈

- **语言/后端**：Python 3.11+，FastAPI
- **数据源**：akshare（免费，无需密钥）
- **存储/缓存**：SQLite（分析结果与原始数据缓存）
- **向量库**：Chroma + 本地 embedding（sentence-transformers / bge-large-zh，可切换）
- **LLM**：DeepSeek（Provider 抽象，可切换模型）
- **前端**：单页 HTML + JS + 轻量 CSS，无构建工具
- **测试**：pytest
- **依赖管理**：uv / requirements.txt + pyproject.toml

## 6. 模块详细设计

### 6.1 core/data —— 数据层

- **指数**：上证指数、深证成指、创业板指、沪深300、中证500 历史日线（`stock_zh_index_daily`）
- **指数估值**：主要指数 PE/PB 历史序列（`stock_index_pe_lg`，乐咕乐股）
- **板块**：东财行业板块名称与行情（`stock_board_industry_name_em`）、板块资金流排名（`stock_sector_fund_flow_rank`）
- **个股**：实时行情快照（`stock_zh_a_spot_em`）、历史日线（`stock_zh_a_hist`）、财务指标（`stock_financial_abstract` / `stock_a_indicator_lg`）
- **基金/ETF**：ETF 行情（`fund_etf_spot_em`）、指数基金信息（`fund_open_fund_info_em`）
- **新闻/公告**：个股新闻（`stock_news_em`）、公司公告（`stock_notice_report`）
- **国债利率**：10 年期国债收益率（`bond_zh_us_rate` 或 `bond_china_yield`）
- **缓存策略**：SQLite 落盘；启动时按 TTL 刷新（指数/估值 TTL 1 天，行情 TTL 当日，新闻 TTL 数小时）；akshare 限流重试。

### 6.2 core/trend —— 大盘长期趋势

输入：主要指数历史行情 + 估值历史 + 国债利率。

计算并输出：

| 指标 | 定义 |
|---|---|
| 长期均线偏离 | 收盘价相对 MA250 的偏离度 |
| 估值百分位 | 当前 PE/PB 在近 5~10 年分布中的百分位 |
| 股债性价比 | 沪深300 盈利收益率 − 10 年期国债收益率，及历史百分位 |

趋势状态判定（规则可测试）：

| 信号 | 条件 |
|---|---|
| 均线 | 收盘 > MA250 × 1.05 为强势，< MA250 × 0.95 为弱势 |
| 估值 | 百分位 > 80% 偏高，< 20% 偏低 |
| 性价比 | 股债性价比百分位 > 80% 股优于债，< 20% 债优于股 |

综合规则：三项信号加权（均线 30% / 估值 40% / 性价比 30%）映射到状态：**低估 / 合理 / 高估**，输出各信号明细与综合结论。

### 6.3 core/sector —— 板块分析

输入：板块行情快照 + 资金流排名 + 板块历史。

打分公式：`板块得分 = RS × 40% + 资金流 × 30% + 动量 × 30%`

- **RS 相对强度**：板块近 1/3/6 月收益 vs 沪深300 同区间收益
- **资金流**：主力资金净流入排名归一化
- **动量**：板块近 20 日区间涨幅归一化

输出：板块排名表（名称、RS、资金流、得分、所属风格），供选股模块与 AI 层使用。

### 6.4 core/stock —— 个股筛选

输入：推荐板块成分股 / 沪深300成分股 + 财务指标 + 估值指标。

打分公式：`标的得分 = ROE × 30% + 成长 × 25% + 估值 × 25% + 股息 × 20%`

- **质量**：ROE（近 3 年均值）
- **成长**：净利润同比增速
- **估值**：PE/PB 相对行业/历史分位（越低越好）
- **股息**：股息率（越高越好）

输出：排序标的列表（含指标明细表）。候选池数据不足时降级为行业龙头名单 + 公开财务数据。

### 6.5 core/portfolio —— 长期配置

输入：推荐板块打分 + 可投标的。

输出配置建议：

- **核心 + 卫星**：核心 70%（宽基指数 ETF）+ 卫星 30%（推荐板块 ETF/基金）
- 卫星板块权重按板块得分归一化
- 定投方案模板 + 再平衡触发规则（如偏离 5%）

### 6.6 core/rag —— 新闻/公告检索问答

- **抓取**：对关注标的/板块抓取近期新闻与公告
- **清洗分块**：去噪、按时间分块、保留标题/日期/来源元数据
- **向量化**：本地 embedding（bge-large-zh），Chroma 存储
- **检索**：query → embedding → 相似度 top-k（可加 BM25 混合），返回带元数据片段
- **引用**：AI 回答必须附来源（标题、日期、链接），由前端展示

### 6.7 ai/ —— DeepSeek 层

- **Provider 抽象**：`LLMClient` 接口；DeepSeek 实现；配置切换模型（环境变量控制）。
- **结构化输出**：所有功能输出用 JSON Schema 约束，返回后校验，失败重试一次。
- **功能**：
  1. `interpret_trend(trend_data)`：把趋势指标转为自然语言状态判断与要点。
  2. `recommend_sectors(sector_table)`：基于打分表生成板块推荐与理由，带置信度。
  3. `recommend_stocks(shortlist)`：基于量化筛选生成标的综合分析报告。
  4. `plan_portfolio(portfolio_data)`：生成长期配置建议与执行说明。
  5. `chat(query, context)`：对话编排，结合分析上下文与 RAG 检索结果作答，必须带引用。
- **约束**：输入仅为分析引擎输出的 JSON；禁止输出未经来源支撑的数字；输出带置信度与不确定性说明；附带投资免责声明。
- **降级**：LLM 调用失败时返回纯确定性分析结果，跳过 AI 解读。

### 6.8 api/ —— FastAPI

- `GET /api/dashboard`：返回看板聚合（趋势指标、板块 Top、推荐标的、数据时点）。
- `POST /api/analyze`：触发完整分析链路，返回结构化分析结果 + AI 解读。
- `POST /api/chat`：对话，请求体含 query 与可选上下文，返回回答 + 引用 + 置信度。
- 全局错误处理中间件：返回结构化错误码；超时设置；请求日志。

### 6.9 web/ —— 前端

- 单页 HTML + 原生 JS + 轻量 CSS，无构建。
- 看板区：趋势状态卡片（含数据时点）、板块排名表、标的推荐表、配置建议区。
- 聊天区：对话流，AI 回答渲染引用链接与置信度标记。
- 首次加载调用 `/api/dashboard`，点击"重新分析"调用 `/api/analyze`。

## 7. 数据流

一次完整分析请求 `POST /api/analyze`：

```
前端 → FastAPI
  → core/data 抓取或读缓存 (akshare)
  → core/trend 趋势指标 + 状态
  → core/sector 板块打分排序
  → core/stock 标的筛选打分
  → core/portfolio 配置建议
  → ai/ 将结构化结果交给 DeepSeek 解读
→ 汇总 JSON → 前端渲染看板 + AI 解读
```

对话请求 `POST /api/chat`：

```
前端 → FastAPI
  → 携带看板上下文
  → (可选) core/rag 检索新闻/公告 top-k
  → ai/chat 生成带引用的回答
→ 返回 回答 + 引用 + 置信度 → 前端
```

## 8. 错误处理（三层降级）

| 故障 | 处理 |
|---|---|
| akshare 网络/接口失败 | 重试 1 次 → 失败则用 SQLite 旧数据，标注数据时点 |
| DeepSeek 超时/调用失败 | 降级：跳过 AI 解读，返回确定性分析结果，看板正常 |
| 数据缺失 | 跳过该条数据，其余正常返回，标注缺失项 |

原则：**AI 是增强层，不是依赖层。**

## 9. 测试与评估

### 9.1 单元测试（pytest）

- 趋势百分位计算、股债性价比计算
- 板块 RS、资金流归一化、打分公式
- 选股多因子打分
- 组合权重归一化
- 数据层 mock akshare 返回，不依赖真实网络

### 9.2 评估体系

- **黄金场景集**：20~30 个已知答案的分析场景（如"PE 处于历史 95% 分位 → 必须提示高估风险"），断言系统输出符合预期。
- **一致性校验**：LLM 解读不得与数据矛盾（数据高估 → AI 不得说便宜）。
- **检索质量**：问答对 Recall@k 指标。
- 评估命令产出报告：`pytest -m eval` / `python -m eval.run`，输出通过率与指标。

### 9.3 端到端

- 跑通"分析某板块 → 筛选标的 → 生成报告"集成测试。
